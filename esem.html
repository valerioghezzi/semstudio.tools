ESEM and Bifactor-ESEM

This page does two things with exploratory structural equation models. It reads the output of a fitted ESEM or bifactor-ESEM solution and reports the reliability and dimensionality indices that are defined for a loading matrix with cross-loadings, saying for each one what the literature defines and what it leaves open. And it writes the Mplus input for the four models a construct-validation study usually compares: the independent cluster confirmatory model, the ESEM model, the bifactor confirmatory model and the bifactor-ESEM model.

What to request from Mplus. OUTPUT: STDYX; — every index here is defined on the completely standardized solution, which for an ESEM block is the rotated solution Mplus prints under the BY headings of that section. The residual variances and any residual covariances printed there are read as well, and the echoed input under INPUT INSTRUCTIONS is read for the target pattern, that is for which loadings the rotation was asked to keep near zero. A warning printed by Mplus is reported and does not remove a result the file supports; what removes a result is a quantity that is missing or inadmissible.

What to do

  1. Fit the model in Mplus. The syntax for each of the four models can be written in the second half of this page.
  2. Add STDYX to the OUTPUT command, so that the line reads OUTPUT: STDYX;, and run the model.
  3. Drop the resulting .out file on the box below. The page reads the rotated standardized loadings of every factor, the correlations between the factors, the residual variances, the residual covariances, and the target pattern from the echoed MODEL command.
  4. Read the indices with the notes beside them. A quantity the literature defines only for a solution without cross-loadings, or only for orthogonal factors, is reported as such and is not computed where its conditions fail.

The fitted model

Drop the Mplus .out file here, or press Enter to choose one.

The file is read in your browser and is not sent anywhere. Windows-1252, UTF-8 and UTF-16 output files are all decoded. When the output has more than one group the page asks which of them to read.

The output holds one standardized solution per group, and the indices describe one solution at a time.
A bifactor solution has one factor on which every item loads by design. The proposal is the factor whose target pattern covers every item; the indices that separate a general factor from the specific ones are reported only when one is designated.

Write the syntax

Describe the model once and the page writes the four inputs that are usually compared, each identified in its TITLE. Nothing is estimated here: what is written is input, to be run in Mplus on your data.

  1. Write the name of the data file, exactly as Mplus will find it, and the list of variable names of that file.
  2. Write one line per factor, in Mplus form: F1 BY x1 x2 x3; The hyphen range is read, so F1 BY x1-x3; is the same line. These are the a priori target items of each factor; every other item becomes a targeted zero in the ESEM blocks.
  3. Choose the estimator and, for the bifactor models, the rotation. Press Write the inputs.

Methods and formulas

What an ESEM solution is

In a confirmatory factor model with an independent cluster structure every item loads on one factor and its loadings on the others are fixed at zero. Exploratory structural equation modeling estimates those cross-loadings instead of fixing them, and identifies the solution by rotation (Asparouhov & Muthén, 2009). A set of factors estimated together in this way is written in Mplus with the same label in parentheses after an asterisk, (*1), and is identified by m2 restrictions for m factors, the number an exploratory factor analysis of the same order requires (Asparouhov & Muthén, 2009). The consequence for measurement is that the correlations between the factors are no longer forced to absorb the covariance that the fixed zeros cannot carry, and are usually smaller than the ones an independent cluster model returns (Marsh, Morin, Parker, & Kaur, 2014).

A bifactor model has a general factor on which every item loads and specific factors on which subsets of items load, all of them mutually orthogonal. Combining the two gives the bifactor-ESEM model, in which the specific factors are estimated as a set with cross-loadings, under an orthogonal rotation (Morin, Arens, & Marsh, 2016). The four models the second half of this page writes are the ones that framework compares, and they are nested in the sense of what they allow rather than in the sense of a difference test: the confirmatory model forbids both cross-loadings and a general factor, the ESEM model allows the first, the bifactor confirmatory model the second, and the bifactor-ESEM model both.

What the page reads

From the STDYX section: the rotated standardized loading of every item on every factor, the correlations between the factors printed under the WITH headings whose two names are factors, the residual variances, and the residual covariances, which are the WITH pairs whose two names are items. From the echoed input under INPUT INSTRUCTIONS: the target pattern, that is which items each factor was asked to load on and which of its loadings the rotation was asked to keep near zero, written with the ~0 notation. Nothing is typed into this half of the page, and no index is computed from a quantity that was not read from the file.

The target pattern is what defines the subscale of a factor, and a coefficient of a subscale needs one. A rotation that specifies no targets, such as BI-GEOMIN, leaves the file with no statement of which items belong to which factor; the page then reports only the quantities that do not need a subscale and says which ones it left out.

Communality with correlated factors

With cross-loadings and correlated factors the variance of an item accounted for by the common factors is not the sum of its squared loadings: the covariance between the factors enters it as well.

hi2=∑k∑lλikλilφkl

Here h2i is the communality of item i, k and l run over the factors, λik is the standardized loading of item i on factor k, and φkl is the correlation between factors k and l, which is one when k and l are the same factor. With two factors the expression is λ2i1 + λ2i2 + 2λi1λi2φ21, and the ratio of the communality to the total variance of the item is the reliability of a single indicator in the sense of Fornell and Larcker (1981). With orthogonal factors every φ off the diagonal is zero and the communality is the sum of the squared loadings.

Omega

The model-based composite reliability of the total of the items targeted on one factor is McDonald's (1970) omega, in the form used for ESEM solutions by Tóth-Király, Bőthe, Rigó and Orosz (2017) and by Morin, Arens and Marsh (2016):

ωf=(∑i|λif|)2(∑i|λif|)2+∑iδii+2∑i<jδij

Here ωf is the omega of the total of the items targeted on factor f, i and j run over those items, λif is the standardized loading of item i on f, δii is the residual variance of item i and δij the error covariance between items i and j. The loadings enter in absolute value, as Tóth-Király and colleagues (2017) write them, so that an item keyed in the opposite direction does not cancel the others.

The last term of the denominator is there only when the model estimates residual covariances between the items of the factor. Bollen (1980) gave the coefficient in that form and Raykov (2001) derived it for the congeneric model with correlated errors; the same denominator is the sum of the elements of the reproduced covariance matrix of those items, which is the form Bentler (2009) works with. Where the model estimates none, the term is zero and the expression is the one printed above it.

A bifactor solution is the exception. There the covariance that a subset of items share beyond the general factor is what the specific factor of that subset stands for, so a residual covariance estimated alongside it is confounded with that factor, and the indices below are derived for a model whose residuals are uncorrelated. A bifactor output that estimates such a covariance is refused with the names of the two items rather than read into formulas that do not cover it; a shared method or a common wording belongs in that model as a further specific factor, orthogonal to the others.

Average variance extracted

AVEf=∑iλif2∑iλif2+∑iδii

Here AVEf is the average variance extracted by factor f, i runs over the items targeted on it, λif is the standardized loading of item i on f and δii its residual variance. This is the coefficient of Fornell and Larcker (1981), computed on the loadings of the factor of interest alone; the variance an item shares with the other factors of the solution is in neither the numerator nor the denominator, so with cross-loadings AVE is not the share of the item's total variance that the model accounts for. That share is the communality above.

Indices that separate a general factor from the specific ones

These are defined for a bifactor solution, in which the factors are mutually orthogonal. The page computes them when every correlation between factors read from the file is zero and one factor has been designated as the general one; with correlated factors it reports why it did not.

Omega for the total of a set of items, in the bifactor form of Rodriguez, Reise and Haviland (2016a), collects the squared sum of the loadings on every factor:

ω=∑k(∑iλik)2∑k(∑iλik)2+∑iδii+2∑i<jδij

Here k runs over the factors of the model, i and j over the items of the total, λik is the standardized loading of item i on factor k, δii its residual variance and δij the residual covariance between two of them, the last term being present only where the model estimates such covariances (Bollen, 1980; Raykov, 2001).

Omega hierarchical keeps that denominator and retains in the numerator the general factor alone; omega hierarchical subscale does the same for a specific factor, over the items of its own subscale (Rodriguez, Reise, & Haviland, 2016a):

ωH=(∑iλiG)2∑k(∑iλik)2+∑iδii+2∑i<jδij

Here ωH is omega hierarchical, λiG is the loading of item i on the general factor, and the remaining symbols are those of the formula above.

Explained common variance is the share of the common variance of the whole set of items that the general factor carries, and the same ratio taken on one item is its item-level explained common variance (Rodriguez, Reise, & Haviland, 2016a):

ECV=∑iλiG2∑i∑kλik2

Here the sums run over every item i of the model and every factor k, so that the denominator is the total common variance of the solution.

Construct replicability is the squared correlation between a factor and the best weighted composite of its items (Hancock & Mueller, 2001), and factor determinacy the correlation between a factor and the regression estimate of its scores:

H=11+1∑iλif21−λif2,FDf=λf′Σ−1λf

Here H is the construct replicability of factor f, i runs over the items targeted on it, and λif is the standardized loading of item i on f. FDf is the factor determinacy of the same factor, λf is the column of the loading matrix belonging to it, and Σ is the correlation matrix the model reproduces, Σ = ΛΛ′ + Δ, whose off-diagonal cells carry the residual covariances where the model estimates them. Rodriguez, Reise and Haviland (2016a) give factor determinacy in matrix form for the whole loading matrix at once, of which this is one diagonal element.

The percentage of uncontaminated correlations is the share of the pairs of items whose correlation carries the general factor alone, counted from the target pattern: a pair is contaminated when both items are targeted on the same specific factor (Rodriguez, Reise, & Haviland, 2016a).

What the page does not compute, and why

Rodriguez, Reise and Haviland (2016a) write these indices for a bifactor model with an independent cluster structure, in which every item loads on the general factor and on one specific factor and no cross-loading is estimated, and they say that the indices can also be computed for exploratory bifactor solutions without giving a modified formula for that case. This page applies their formulas to the matrix as it stands, so that a cross-loading enters the sums of the factor it belongs to, and reports beside the table that this is an application of formulas written for a stricter structure. The alternative, computing the coefficients on the target loadings alone and discarding the cross-loadings, would report a variance the model does not imply.

With correlated factors, omega hierarchical, explained common variance and the percentage of uncontaminated correlations are not reported. The variance of a total is then not the sum of the parts each factor contributes, because the covariances between the factors belong to it as well, and a share attributed to one of several correlated factors is not determined by the model. Omega for each factor, the average variance extracted, construct replicability and the communalities are reported, since none of them requires that partition.

Factor determinacy is computed from the reproduced correlation matrix when the factors are orthogonal. Mplus prints the determinacies of any solution directly when the OUTPUT command carries FSDETERMINACY, and that is the value to report for a solution with correlated factors; the option is refused for models whose indicators are all categorical.

Nothing on this page is a difference test between the four models. Their fit is compared as they are estimated, and the comparison rests on the fit indices, on the size and the pattern of the cross-loadings and, for the bifactor models, on whether the specific factors retain enough variance to be interpretable, which is what omega hierarchical subscale reports.

The syntax the page writes

The four inputs differ only in the MODEL command and in the ANALYSIS command. The confirmatory input writes one BY statement per factor with its target items. The ESEM input writes the same factors as one set, marked (*1), with every non-target item listed with the ~0 notation under target rotation, which asks the rotation to keep those loadings near zero without fixing them (Asparouhov & Muthén, 2009; Morin, Arens, & Marsh, 2016). The bifactor confirmatory input adds a general factor on every item and fixes every correlation between factors at zero. The bifactor-ESEM input writes the general factor and the specific factors as one set under an orthogonal rotation, which makes them orthogonal by construction, in the form used by Morin, Arens and Marsh (2016). Where the rotation chosen is BI-GEOMIN or BI-CF-QUARTIMAX, the bifactor input lists every item on every factor of the set and lets the rotation place them.

Each input ends with OUTPUT: STDYX;, which is what the first half of this page reads, and with whatever else was ticked. No input carries a MODEL CONSTRAINT block: the coefficients are computed here, from the standardized solution the run prints, and writing them a second time inside the input would put two answers to the same question in front of the reader.

Self-test

Adding ?selftest=1 to the address of this page runs its numerical checks in the browser and prints the outcome at the top. They cover the communality with correlated factors against a matrix product computed a second way, omega and the average variance extracted against their formulas on random loading matrices, the effect of a residual covariance on the coefficients defined on the variance of a total and its absence from those defined on single items, the bifactor indices against the values the independent cluster case gives, factor determinacy against an inverse obtained by Gauss-Jordan elimination, the reading of the target pattern from the echoed input, and the syntax the builder writes for each of the four models.
